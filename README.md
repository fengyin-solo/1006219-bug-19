# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries:v2` 与
  `hydropower-plant-om:unit-ledger:v1` 两项。

## 机组并网台账（列表、看板、发电计划同源）

机组运行的台数、容量与小时数不再各算各的，统一由「机组表 + 并网时段台账」实时派生
（`src/data/unit-ledger.ts`），机组列表、运营概览、发电计划页调用同一个 `buildUnitBoard`：

- **动作即记账**：开机并网开出一条并网时段；停机转备、登记故障把该时段收口。
  故障停机区间不开时段，修复后重新并网按新时段起记，小时数只计实际并网段，不再整段顺延。
- **派生口径**：运行中台数 = 状态「运行中」；备用容量 = 「停机备用」机组额定出力之和；
  故障台数 = 「故障停机」；**可用机组 = 运行中 + 停机备用**（故障、待启动不计入）。
- **重复登记故障只算一次**：同一台机组故障未消除前再次登记直接拒绝，不重复扣减台数。
- **取值优先级**：累计运行小时以并网时段明细重算为准（可逐段核对的一手凭证），
  机组自带的累计字段仅在查不到任何明细时保底，动作与回填都会把重算值同步回写机组清单。
- **存量回填**：早年「只有开机、没有停机」的开口时段，其后还有并网记录的收口到下一条
  记录时刻；其后再无记录的封到开机当年 `12-31 23:59`，不跨年臆测，并在运营概览逐条列明。
- **补记提交**：整套提交、整套受理或整套退回；幂等键为「机组 + 并网时刻」，
  以最先入库的一稿为准，后到的整套退回并留痕，与已退回批次完全相同的重复提交只保留一条。
- **班组隔离**：顶栏切换值班班组；越权替别的班组提交台账或操作其人员一律拒绝，
  明细、批次、值班清单只见本班记录（全厂台数看板不受影响）。提交人必须在本班
  「在场」值班清单内，办理离场即失去提交资格——值班清单与台账联动。
